# Codex 接入开发契约

本契约覆盖实现、测试、安装、升级、恢复和交付。
历史页面切换方案和全局后端重定向方案均不能作为当前实现依据。

## 接口选择顺序

1. 每项操作首先检查原版 Codex Desktop IPC 的实际能力，校验应用身份、账户、协议及任务所有者。
2. 已有桌面任务的读取、流式、发送、干预、停止及设置保留原所有者接入路径。
3. 只有对应 IPC 能力确实缺失，才使用 Desktop 自带或管理的原版运行时启动额外进程。
   记录能力缺口及验证证据，不能因为超时、断线、未知响应或调用失败就换宿主重试。
4. Filo 新建任务可以由额外原版运行时创建并执行。已有任务只有在显式发送或修改设置时，
   才能在确认同一账户的原生线程空闲、没有 IPC 所有者且没有活动写入者后恢复；分配前须再次
   检查所有者，原生 resume 写锁仍是最终准入边界。Filo 自己创建的已有任务也须在替换失效
   执行器前重新取得精确任务的空闲证据；创建来源本身不能代替空闲证明。浏览和订阅不能分配写入者，活动或未知
   状态不能恢复。IPC 所有者存在时始终使用它；超时、失败和未知结果不能触发换宿主或重放。

IPC 仍是优先路径，额外进程按能力缺口使用。当前列表和历史的有界只读投影不能取得执行
所有权，也不能被描述为 IPC 支持。版本号只作诊断，禁止固定原生版本、安装路径或哈希准入。

## 禁止桌面操作与 CLI 前置条件

任何流程都不能切换桌面页面、改变焦点、模拟键鼠或借助可见命令窗口。New Chat 不依赖
桌面控制。不得为测试或安装关闭、重启或修改正常使用的 Codex。手机 UI 需要独立进行设备验证。

仅安装 Codex Desktop 必须足够。无需安装 Codex CLI、npm 全局包、配置 PATH 或填写
codex.exe 路径。按所选账户和官方应用身份动态解析其运行时，客户端升级后重新发现。
原版客户端暂未运行、未完成运行时准备或更新中的状态必须明确，不能损坏正常客户端。

## 故障隔离与原生所有权

Filo 服务停止、崩溃、被杀、断联、被卸载、文件消失或升级失败，都不能影响正常 Codex。
其启动、登录、历史恢复、生成、原生工具、权限、设置和本机任务均须保持独立。
Filo 不得修改 Codex 程序、启动路由、全局环境、原始会话或认证文件来完成接入。

原生执行不得依赖 Filo 网关的进程存活。服务消失时，已经接受的原生回合继续执行；
不能仅让辅助 PID 存活却失去工具输入或生成能力。额外运行时必须独立监督自己的生命周期，
生成结束后释放写所有权，使正常 Codex 可以恢复同一任务，不能依赖重新启动 Filo 解锁。
正常更新和卸载不能结束活动原生任务；所有清理限于明确识别的 Filo 资源。

对普通桌面或其后端发信号、杀同名进程、重写数据库、注入核心代码、全局重定向，以及
把排队输入当作占位持久化均禁止。服务恢复不能重放创建、发送、设置或归档请求。

## New Chat 的交付条件

空白输入页和键盘立即出现，不预创建任务；在显式 Send 时才进行网络操作。
验证实际原生任务 ID、初始模型／Thinking／Service Tier、第一条用户输入的接收身份和唯一性。
返回空任务、收到 HTTP 成功或出现本地气泡不能代替原生接收证据。结果不明必须保留未知状态。

**严禁"创建空会话"接口**：远程会话的创建必须和第一条用户消息绑定，
同一个原子操作。任何"先创建空会话、后发送第一条消息"的时序都违反本契约。合规实现：
创建端点必须携带第一条消息（`POST /v1/sessions` 带消息体）；服务端在同一请求内完成 thread/start 与 turn/start，并把原生会话 ID 返回给客户端。原生 Codex 自行生成会话 ID（忽略客户端提供的 threadId，已实测确认），客户端以返回的 ID 作为后续 send 的目标。任何暴露"创建空会话"端点（如 `POST /v1/sessions` 不带消息体）
的实现都不合格，任何先调 create 再调 send 的客户端流程都不合格。

完整链路还包括历史、流式、干预、停止、重命名、原生归档、故障恢复，以及由正常原版
运行时重新打开同一任务。不得降低原有手机分页、动画、图片、状态或错误反馈语义。

## 会话遥控与确认

Desktop 在线时，创建必须携带首条消息；已有会话通过当前 IPC 所有者继续。没有所有者的
空闲会话只在上述显式 mutation 的准入边界恢复，无新增 prepare/resume 端点。
`/settings` 为部分更新：缺省不变，`serviceTier:null` 为原生 Default；成功必须有原生
应用与读回证据，Android 随后读取原生快照。Desktop IPC 的读回须来自同一所有者，且每个
请求字段都须有请求后的完整快照或对应字段更新；消息、用量和其他设置字段的更新不能
替代该字段的新证据。模型、Thinking 和 tier 可选值来自原生模型目录。

运行时和目录必须保留已完成回合 ID，执行器退役不能抹掉终态、最后确认设置和使用量。
`notLoaded` 只表示当前没有加载状态，不能单独证明完成。有界只读原生记录中直接观察到的
最新轮次终态投影为 `idle`，供列表和聊天一致结算；缺失、超出读取边界或有更新的开始记录时
仍保持未知，不能仅凭索引中的旧完成记录结算。未知 service tier 与已确认 Default
必须区分。GET 与 paged SSE 可返回最多 128 个按 clientId 唯一的
`inputReceipts:[{clientId,turnId,messageId}]`，仅包含原生确认的非空身份，独立于可见历史页。
发送确认匹配精确回合；Stop 的等待状态须同时满足 HTTP 完成与该精确原生回合结束或替换。

验收须覆盖创建、完成、执行器退役、目录结算、重新打开、设置读回及再次发送的连续链路，
以及分页外消息确认、Stop 的两种到达顺序、断流恢复和原生写锁冲突。自动测试与真实原生
账户、安装升级、加密公网连接和手机 UI 验收分别留证。

## 必须提供的证据

- 在无 PATH CLI、错误 PATH CLI、Desktop 更新和运行时暂不可用情况下验证发现及恢复。
- 活动任务期间分别停止、强杀、移除 Filo 网关和用户辅助连接，证明原生回合和工具继续推进。
- 故障后无需 Filo 恢复，原生任务能独立结束并释放所有权；另一个原版运行时可恢复同一历史。
- 记录原桌面及后端进程身份、配置／凭据未变、消息和输入 ID、模型请求计数及退出结果。
- 正常卸载／更新面对活动原生执行时保持安全，故障恢复不重发副作用操作。
- 检查所有后台启动入口实际无控制台句柄；仅指定 Hidden 不算验收通过。
- 全量回归、改动前后等价性、代码卫生、文件行数和目标电脑及必要 APK 实际部署分别留证。

缺少任何相关证据时，只能记录尚未验证。禁止使用桌面自动化来补齐本清单。
